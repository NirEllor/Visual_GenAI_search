# The impact of latent dimension on distilled flow matching models's FID

**Report date:** October 20, 2026
**Repository:** https://github.com/NirEllor/Distillation_Research
**Advisor:** Prof. Raanan Fattal

---

## Abstract

This study measures how the dimension of an autoencoder latent space (64, 128, 256, 384, 512, 1024) affects the Fréchet Inception Distance (FID) of two models in a flow-matching dataset-distillation pipeline on CIFAR-10: a multi-step flow-matching **teacher** and a one-step **student** trained only on synthetic latents generated by that teacher. Students are trained at four synthetic dataset sizes (50k, 100k, 150k, 200k) for every dimension, giving 24 student configurations. All results are from one training configuration (Configuration A). The report also summarises an earlier sequence of experiments from project notes and the repository's latent-distribution analysis.

## 1. Research Question

**Primary question.** How do student FID and teacher FID depend on latent dimension and on the number of synthetic training samples?

**End question.** Can a small one-step student do better when it is trained on a latent space at a "sweet spot" dimension, rather than on a larger latent space? Answering this requires comparing student FID across dimensions at each dataset size, and comparing each student with its own teacher.

**Background observation (from project notes).** Increasing the autoencoder latent dimension improved reconstruction FID, but the generative FID of the teacher, and of the distilled student, became worse.

| 4 | `step4_evaluate.py` | `--generate` (10k samples), `--decode`, `--metrics` (clean-fid, IS, AE-FID), `--plot` |

### 2.2 Flow matching

- **Training (teacher):** x_t = (1 − t)·x₀ + t·x₁ with constant-velocity target v = x₁ − x₀; loss MSE(v_θ(x_t, t), v).
- **Teacher sampling:** Euler ODE, 200 steps, from noise to latent.
- **Student training:** no time sampling and no teacher forward pass. Each cached pair (x₁, x₀) gives input x_t = x₁ and target v = x₁ − x₀, so the student learns a one-step map. The student loss is MSE(student(x₁), x₁ − x₀).
- **Student sampling:** one forward pass.

### 2.3 Architectures and parameter counts

Parameter counts were computed with `param_count` (`models/denoiser.py`) and `ConvAutoencoder` (`models/autoencoder.py`). The model code is unchanged since the Configuration A training code (`git diff b20dcfc^ HEAD -- models/` is empty), so the descriptions below apply to Configuration A.

Notation: `C = dim / 16` is the number of latent channels. A latent vector of length `dim` is stored as a (C, 4, 4) spatial map.

**Autoencoder (`ConvAutoencoder`).** Trained in Step 0 with LPIPS loss (VGG backbone, frozen), then frozen. Encoder:
- `encoder_in`: Conv 3×3, 3 → 128 channels (32×32)
- `down1`: ResNetBlock(128), then Conv 3×3 stride 2, 128 → 128 (→ 16×16)
- `down2`: ResNetBlock(128), then Conv 3×3 stride 2, 128 → 256 (→ 8×8)
- `down3`: ResNetBlock(256), then Conv 3×3 stride 2, 256 → 256 (→ 4×4)
- `encoder_out`: ResNetBlock(256), GroupNorm(32), GELU, Conv 1×1, 256 → C

Decoder:
- `decoder_in`: Conv 1×1, C → 256
- `up1`: ResNetBlock(256), then ConvTranspose 3×3 stride 2, 256 → 256 (→ 8×8)
- `up2`: ResNetBlock(256), then ConvTranspose 3×3 stride 2, 256 → 128 (→ 16×16)
- `up3`: ResNetBlock(128), then ConvTranspose 3×3 stride 2, 128 → 128 (→ 32×32)
- `decoder_out`: ResNetBlock(128), GroupNorm(32), GELU, Conv 3×3, 128 → 3

ResNetBlock: GroupNorm(32) → GELU → Conv 3×3 → GroupNorm(32) → GELU → Conv 3×3, with a residual addition. The encoder is deterministic: `encode` returns the latent as its first output and a zero log-variance (kept only for interface compatibility). Latent dimension must be divisible by 16.

Autoencoder parameters: dim 64: 7,983,111; 128: 7,985,163; 256: 7,989,267; 384: 7,993,371; 512: 7,997,475; 1024: 8,013,891. The autoencoder is almost the same size at every dimension; only the 1×1 projections to and from C channels change.

**Teacher (`TeacherDenoiser`, FiLM-conditioned `ConvDenoiser`).** Input: x_t (dim values) → reshape to (C, 4, 4) → Conv 1×1 to `hidden` channels → n × `ConvResBlock` → GroupNorm → Conv 1×1 to C channels → flatten to dim values (the predicted velocity). Time embedding: t × 1000 → sinusoidal embedding (256) → Linear(256, 256) → GELU → Linear(256, 256).

Each `ConvResBlock`: GroupNorm → Conv 3×3 → GELU → FiLM (scale and shift from a Linear(256, 2·hidden) applied to the time embedding) → GroupNorm → Conv 3×3 → residual addition.

Hidden width and block count depend on dimension: dim ≤ 128 → hidden 256, 8 blocks; dim 256–512 → hidden 384, 10 blocks; dim 1024 → hidden 512, 12 blocks. Steps 3a and 4 sample with 200 Euler steps.

**Student (`StudentDenoiser`, untimed).** Input: x (dim values) → reshape to (C, 4, 4) → Conv 1×1 to `hidden` channels → 4 residual blocks → GroupNorm → Conv 1×1 to C channels → flatten. Each block: GroupNorm → Conv 3×3 → GELU → GroupNorm → Conv 3×3, with a residual addition. There is no time input; the `t` argument is ignored. Sampling is a single forward pass. `hidden = max(256, 8·C)`: 256 for dims 64–512 and 512 for dim 1024.

Teacher and student parameter counts:

| Dimension | Teacher parameters | Student parameters |
|---:|---:|---:|
| 64 | 10,636,548 | 4,727,556 |
| 128 | 10,638,600 | 4,729,608 |
| 256 | 28,683,920 | 4,733,712 |
| 384 | 28,690,072 | 4,737,816 |
| 512 | 28,696,224 | 4,741,920 |
| 1024 | 60,016,704 | 18,953,792 |

For dimensions 64–512 the student has almost the same number of parameters (about 4.73M) at every dimension, because only the input and output projections depend on C. The dimension-1024 student has about four times as many parameters. Any comparison of student dimensions must take this into account.

The notes record the central phenomenon: better latent reconstruction did not make the latent distribution easier to model generatively.

### 3.2 Autoencoder debugging

- **Early autoencoder versions.** Some early architectures and loss settings gave high AE FID (about 147–172 for dims 128–1024). Candidate causes considered: encoder/decoder capacity, blur from the reconstruction objective, ConvTranspose artefacts, mismatch between pixel losses and FID, output saturation, and bottlenecks.
- **Removing LPIPS (L1 × 1.5 reconstruction loss).** AE FID by dimension: 64: 119.96, 128: 90.08, 256: 55.98, 384: 38.34, 512: 30.58, 1024: 27.09. Better reconstructions did not remove the high-dimensional teacher failure.
- **LPIPS with VGG at 64×64 resolution (dim 1024).** AE FID improved from about 15.1 to 13.0 (recorded value 12.9789; L1 = 6.4354; LPIPS = 0.0262).
- **KL regularisation.** A KL-style term was tested. No significant improvement in AE behaviour or in the dimensionality trend was recorded.

### 3.3 Latent normalisation

Per-coordinate normalisation changed the results and improved some settings, notably around dimension 256. It did not remove the high-dimensional degradation. Normalisation mattered, but was not enough to explain dimensions 512–1024.

### 3.4 Synthetic dataset size

Larger synthetic sets were tested for selected dimensions. At dimension 256, student FID improved from about 124.25 with 250K samples to 87.84 with 2M samples. Dimensions 64 and 128 improved only slightly; dimensions 384–1024 did not improve enough to remove the dimensionality trend. Conclusion recorded in the notes: larger latent spaces may need substantially more synthetic data, but data size alone does not explain the severe degradation at the largest dimensions.

### 3.5 Teacher versus student

Teacher and student curves were strongly correlated across the stages. The student often looked like the teacher curve shifted upwards. The high-dimensional problem was therefore not only a distillation failure; the student inherited part of the teacher's problem.

### 3.6 Model capacity

Increasing teacher capacity improved absolute performance in some cases, and moving from an MLP-style model to a convolutional one reduced part of the gap between low and intermediate dimensions. Increasing capacity did not remove the dimensionality trend.

### 3.7 Flow-matching sanity test on Gaussian data

Flow matching was trained on synthetic Gaussian distributions for dimensions 64–1024. Recovered mean error was about 0.05 and standard-deviation error about 0.01–0.02, with no growth in error with dimension. The core implementation therefore appeared capable of high-dimensional transport.

### 3.8 Diagonal-Gaussian latent baseline

Each latent coordinate was modelled as an independent Gaussian, sampled, decoded, and scored by FID.

| Dimension | Diagonal-Gaussian FID (approx.) |
|---:|---:|
| 128 | 129 |
| 256 | 172 |
| 512 | 213 |
| 1024 | 222 |

Teachers at the same stage were approximately 46 (128), 57 (256), 56 (512), and 65 (1024). The notes conclude that the autoencoder latent distribution has strong non-linear, dependent structure that the teacher captures and an independent Gaussian does not.

### 3.9 Real versus generated latent statistics

Generated latents had lower variance and smaller pairwise distances than real encoded latents. The gap grew with dimension, especially at 1024. The notes describe this as latent-space contraction (variance collapse). Section 3A checks this against the repository results.

### 3.10 Later teacher sweep (intermediate stage)

Teacher FID at an intermediate stage: 64: about 77; 128: about 76; 256: about 70; 384: about 59; 512: about 56; 1024: about 56. Students at 200K samples: 64: about 80; 128: about 86; 256: about 94; 384: about 79; 512: about 76; 1024: about 83.

### 3.11 Fixed conditioning width (configuration issue)

The notes report that the Flow Matching `UNetModelWrapper` used an internal `latent_dim = 256` for every experiment, while the autoencoder latent dimension varied. The sweep therefore changed two things at once: information content of the latent and conditioning capacity of the model. The corrected proposal was `unet_latent_dim = num_latents`, with the full teacher sweep retrained. The earlier fixed-256 runs were treated as a separate branch.

*Note: the current repository implements conditioning width through `TeacherDenoiser` in `models/denoiser.py`; the `UNetModelWrapper` named in the notes is not in the current code.*

### 3.12 Corrected teacher sweep (from notes)

Recorded best FIDs after the correction: 64: 10.07; 128: 9.81; 256: 9.90; 384: 12.67; 512: 9.63; 1024: 9.70. The notes state that dimension 384 had reached only about 78,200 optimisation steps, while dimension 512 reached about 312,800, and that the 64/128 runs stopped earlier because of a four-day training limit. The notes conclude that comparisons at equal epochs or wall-clock time can mislead when optimiser step counts differ, and that the sweep should be compared at approximately equal step counts.

*These values are not in the repository and are on a different scale from the Configuration A results in this report (Section 6.2).*

### 3.13 Student conditioning issue

At one stage the distilled student did not receive the AE latent that the teacher was conditioned on. Teacher outputs depend on both the source noise and that latent, so the student faced a one-to-many mapping. The proposed correction is Student(noise, latent) → teacher endpoint. The notes describe the experiment as closer to endpoint or transport distillation than to ordinary flow-matching vector-field training.

### 3.14 Synthetic dataset construction

The grid is 6 dimensions × 4 synthetic sizes = 24 students. Later, larger sizes were built as nested prefixes of one synthetic pool, so that different sizes differ only by added examples.

### 3.15 Hypothesis summary (from notes)

| Hypothesis | Status in notes |
|---|---|
| A: poor AE reconstruction | Mostly rejected |
| B: insufficient student data | Partially supported (helped at dim 256; not enough at 512–1024) |
| C: insufficient teacher capacity | Partially supported |
| D: latent scale / normalisation | Partially supported |
| E: Flow Matching cannot work in high dimensions | Not supported (Gaussian sanity test) |
| F: harder latent geometry at higher dimensions | Supported by several observations, not proven as the sole cause |
| G: implementation and configuration confounds | Strongly supported (fixed conditioning width, unequal step budgets, student missing conditioning) |

## 7. Observations

These observations describe the recorded values. They do not assign a quality rating to any value.

### 7.1 What FID measures

FID is the Fréchet distance between Gaussian fits to Inception features of generated and real images: FID = ‖μ_r − μ_g‖² + Tr(Σ_r + Σ_g − 2(Σ_r Σ_g)^½). A lower FID means the two feature distributions are closer under this model. FID depends on the protocol (sample count, reference set, feature extractor), so values from different protocols are not directly comparable.

### 7.2 Student FID across dimension and dataset size

- Student FID falls as the dataset grows, for every dimension. The fall is largest at dimension 1024 (−18.76) and smallest at dimension 64 (−3.02).
- The ordering across dimensions is the same at every dataset size. No interior dimension has the lowest student FID among the six tested values.
- The gap between student FID and teacher FID at 200k grows with dimension (from +4.00 at 64 to +13.41 at 1024).

### 7.3 Sweet-spot question

Within the six tested dimensions, the sweet spot for students is the smallest tested dimension, 64, at every dataset size. The data therefore does not show an interior optimum. Because 64 is the smallest tested value, the optimum could lie below 64; this was not tested.

Two confounds should be kept in mind when comparing dimensions:

- **Student capacity.** Student parameter counts are nearly constant for dimensions 64–512 (about 4.73M) and about four times larger at 1024 (about 19.0M). The dimension-1024 result therefore combines a larger latent with a larger student.
- **Teacher quality.** Teacher FID is lowest at 128, not 64. Student FID is lowest at 64. The student does not simply inherit the teacher ordering, so the teacher's quality alone does not determine the student ordering.

## 8. Limitations

1. **Single seed.** The configuration is one training run per dimension. Variation across seeds is not measured, so differences of about one FID point should not be interpreted.
2. **Limited dataset sizes.** The largest synthetic set is 200k. The notes report a 2M run at dimension 256 only; that run is not in the repository. Trends at larger sizes are not measured here.
3. **Unmatched student capacity.** Student parameter counts differ at dimension 1024 (Section 2.3).
4. **Optimiser budget.** Training uses a fixed number of epochs, which gives different numbers of optimiser steps across dimensions. The notes raise this as a concern for the earlier sweep. The step counts for the current runs are not recorded in the repository.
5. **Protocol differences.** Values from the project notes (Sections 3.1–3.12) are not reproducible from the repository and are not compared with the Configuration A values.
6. **Checkpoint provenance.** The Configuration A metrics file (2026-07-05) is older than its autoencoder checkpoints (2026-07-06), and the teacher and student checkpoints are not in the repository. The FIDs cannot be recomputed here.
7. **Six dimensions only.** Interpolation between the tested dimensions is not possible; the sweet spot, if any, may lie between or below the tested values.

## 11. Conclusion

Student FID increases with latent dimension at every synthetic dataset size from 50k to 200k, and increasing the dataset lowers student FID at every dimension. Dimension 64 gives the lowest student FID at all four sizes. Among the six tested dimensions there is no interior sweet spot for students. The gap between student and teacher FID widens with dimension, and dimension 1024 also has about four times the student parameters of the other dimensions, so its result combines latent size with student capacity.
